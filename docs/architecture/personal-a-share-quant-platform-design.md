# 个人 A 股低频量化研究平台需求规格

文档状态：已确认设计，待用户书面审阅  
版本：1.0  
日期：2026-07-30  
使用对象：个人自有资金量化研究者  

## 1. 文档目的

本文定义个人 A 股量化体系的长期建设蓝图，以及一期 MVP 的产品范围、工程架构、功能要求、非功能要求和验收标准。本文是后续实施计划、任务拆分和测试验收的依据。

系统以低频策略为主，最高数据与决策频率为日频。系统不追求高频、盘口预测或低延迟交易，而优先保证数据时点正确、研究可复现、回测可信、组件边界清晰，以及未来从研究平台平滑演进至模拟和实盘系统。

## 2. 背景与核心诉求

用户希望建设一套供个人长期使用的 A 股量化体系，解决以下问题：

1. 统一管理长期日频行情、财务、证券状态和衍生因子数据。
2. 通过 Python 和 Notebook 高效开展 ETF 轮动、股票多因子等策略研究。
3. 在回测中真实模拟 A 股交易制度和无法成交情形，避免未来函数与过度乐观结果。
4. 对每次实验记录代码、参数、数据和结果，实现复现、比较和追溯。
5. 通过本地 Dashboard 集中查看数据状态、实验结果、风险、归因和任务日志。
6. 一期使用 BaoStock，后续正式阶段切换 TuShare，不让策略和展示层绑定具体数据供应商。
7. 为后续组合管理、模拟交易、券商接入、实盘风控和对账预留稳定扩展边界。

## 4. 产品目标与原则

### 4.1 长期目标

长期系统覆盖以下闭环：

```text
数据采集 → 数据治理 → 策略研究 → 回测验证 → 组合构建
→ 风险管理 → 模拟/实盘执行 → 对账 → 绩效归因 → 运营监控
```

### 4.2 一期目标

一期交付可独立使用的研究与回测平台：

- 完成 20 年日频数据的版本化管理。
- 建立可复用的股票池、因子、组合和回测模块。
- 通过 ETF 轮动与股票多因子验证两类典型研究流程。
- 建立 Notebook 策略实验室和实验登记机制。
- 建立本机 Dashboard，集中展示数据、实验、回测、因子和任务状态。
- 证明 BaoStock 可以在不影响上层研究逻辑的前提下替换为 TuShare。

### 4.3 工程原则

- 时点正确：只能使用信号产生时已经公开且系统可获得的数据。
- 可复现：相同代码、配置、数据快照和环境得到相同结果。
- 单一核心：Notebook、批处理和 Dashboard 共享正式 Python 核心包。
- 数据源隔离：策略层不引用 BaoStock 或 TuShare 专有接口和字段。
- 失败关闭：关键数据质量检查失败时，不发布研究快照。
- 幂等执行：同一任务重复运行不产生重复数据或冲突结果。
- 结果不可覆盖：新实验生成新 ID，保留完整历史和审计信息。
- 配置化规则：板块交易制度、费用和回测假设不永久硬编码。
- 先单体后扩展：一期不引入微服务、消息队列或分布式基础设施。

## 5. 范围定义

### 5.1 一期包含

1. BaoStock 采集客户端与规范数据映射器。
2. Raw、Curated、Feature 三层数据仓库。
3. 证券主数据、交易日历、日行情、复权、证券状态和财务数据处理。
4. 数据质量检查、版本管理和每日数据快照。
5. Jupyter Notebook 策略实验室。
6. 历史时点股票池。
7. 因子注册、计算、处理和分析。
8. ETF 轮动基准策略。
9. 股票多因子基准策略。
10. 日频组合构建与 A 股回测引擎。
11. 实验登记、比较、标记和归档。
12. 绩效、风险、费用和归因报告。
13. 本机 Streamlit Dashboard。
14. 自动化测试、日志和性能验收。

### 5.2 一期不包含

- 分钟、Tick、盘口或实时行情。
- 真实券商账户连接。
- 真实订单生成、审批、发送和撤单。
- 模拟盘和无人值守交易。
- 融资融券、卖空、期货、期权和其他衍生品。
- 北交所、港股和境外市场。
- 可视化拖拽策略编辑器。
- 公网部署、多人协作和复杂权限管理。
- 移动端 App。
- 自动参数寻优后直接发布策略。
- 任何形式的收益承诺。

## 7. 数据系统需求

### 7.1 数据分层

#### Raw 原始层

- 原样保存供应商返回数据和下载批次信息。
- 原始文件不可就地修改或覆盖。
- 相同数据的供应商修订形成新版本。
- 保留来源、请求参数、下载时间和结果摘要。

#### Curated 标准层

- 统一证券代码、交易日、字段名称、类型、单位和缺失语义。
- 统一前复权、后复权和不复权的计算入口。
- 保存上市、退市、停牌、风险警示和板块等历史状态。
- 财务数据按公告时间和系统可用时间进行时点化。
- 为 BaoStock 与 TuShare 建立统一字段模型。

#### Feature 因子层

- 保存可复用、带版本的因子结果。
- 因子结果关联定义版本、输入快照和计算参数。
- 支持按交易日、因子、证券和策略读取。
- 支持增量计算和缓存复用。

### 7.2 必需时间字段

适用的数据集至少应提供其中相关的时间字段：

- `trade_date`：市场交易日。
- `effective_date`：信息开始生效的日期。
- `announced_at`：信息公开时间。
- `available_at`：系统可使用时间。
- `ingested_at`：写入本地系统的时间。
- `source`：数据来源。
- `source_version`：来源版本或下载批次。

财务查询必须确保 `available_at` 不晚于策略信号计算时刻。

### 7.3 数据快照

每个可研究交易日生成不可变数据快照，至少包含：

- 交易日历和证券主数据版本。
- 当时可用的行情、财务、复权和证券状态。
- 历史时点股票池。
- 数据质量检查摘要。
- 快照 ID、生成时间和来源版本。

只有通过关键质量检查的快照才能标记为“可研究”。

### 7.4 数据质量规则

至少检查：

- 交易日缺失或重复。
- 证券代码映射失败。
- 主键重复。
- 价格、成交量、成交额缺失。
- 高低价逻辑错误和异常涨跌幅。
- 复权因子异常跳变。
- 上市、退市、停牌和风险状态冲突。
- 财务公告时间缺失或倒置。
- 全市场记录数异常变化。
- BaoStock 与未来 TuShare 同区间数据差异。

质量事件分为信息、警告、严重、致命四级。严重或致命事件影响持仓候选、关键字段或全市场覆盖时，不得发布快照。

## 8. 策略实验室需求

### 8.1 使用方式

- 研究者通过 Jupyter Notebook 编写和运行 Python 实验。
- Notebook 只能通过公开 Python API 访问数据、股票池、因子、组合、回测和指标。
- Notebook 不复制正式回测引擎，也不得直接修改 Raw 或 Curated 文件。
- 可将通用逻辑从 Notebook 提升为正式 Python 模块并加入测试。

### 8.2 实验流程

```text
选择数据快照与样本区间
→ 定义策略与参数
→ 运行因子分析或回测
→ 登记实验
→ 生成指标、图表和日志
→ 在 Dashboard 比较
→ 标记为基线、候选或废弃
```

### 8.3 实验元数据

每次实验必须保存：

- 唯一实验 ID、名称、策略类型和标签。
- 创建时间、开始时间、结束时间和运行状态。
- Git 提交版本。
- Python 与依赖环境版本。
- 数据源、数据版本和数据快照 ID。
- 样本区间和基准指数。
- 股票池规则。
- 因子定义、方向、权重和处理参数。
- 调仓频率和组合约束。
- 初始资金、费用、滑点和成交假设。
- 随机种子；不使用随机过程时明确记录为不适用。
- 完整绩效指标。
- 结果文件、图表、日志和报告位置。
- 研究结论及基线、候选或废弃状态。

### 8.4 实验操作规则

- 复制实验仅复制配置，必须生成新实验 ID。
- 已完成实验的参数和结果不可覆盖。
- 失败或取消实验保留元数据和最佳努力日志，但不得标记为成功；进程崩溃可能丢失尚未刷新的日志窗口。
- Dashboard 指标必须能追溯到唯一实验。
- 同一实验配置重复运行应产生可比较且确定的结果。

## 9. 基准策略需求

### 9.1 ETF 轮动

该策略用于验证资产池、趋势或动量信号、排名、调仓、费用和绩效流程。

必须支持：

- 配置 ETF 池。
- 计算多窗口动量、趋势和波动率类指标。
- 选择排名靠前且满足趋势过滤的 ETF。
- 配置持有数量、权重、调仓频率和现金处理规则。
- 输出每期信号、目标权重、成交模拟和绩效结果。

### 9.2 股票多因子

该策略用于验证历史股票池、财务时点、因子处理、组合约束和大规模回测。

必须支持：

- 沪深主板、创业板、科创板历史证券范围。
- 按上市天数、风险状态、停牌、流动性等条件构建股票池。
- 质量、估值、动量和风险四类基础因子。
- 默认按 `MAD 去极值 → 截面标准化 → 方向调整 → 类别聚合` 处理因子；显式声明行业依赖时，可使用信号日 as-of 行业状态做分组、中性化或约束，未声明运行保持原公式不变。行业状态的统一语义见[行业分类 PIT 整体设计](industry-classification-pit-design.md)。
- RankIC、滚动 RankIC、分层收益、覆盖率和相关性分析。
- 因子加权合成和股票排名。
- 持仓数量、个股权重、换手和流动性约束。
- 输出每期股票池、因子、评分、目标权重、成交模拟和绩效结果。

两套策略是系统验收样例，不构成收益承诺或生产策略推荐。

## 10. 回测引擎需求

### 10.1 时间语义

默认采用保守时间线：T 日收盘后使用当时已可获得的数据生成信号，最早在 T+1 日模拟成交。使用 T 日收盘信息时，不允许默认按 T 日收盘价成交。

### 10.2 A 股约束

回测规则必须配置化，并支持：

- 股票买入后的 T+1 可卖约束。
- 按证券、板块、日期适用的涨跌幅规则。
- 停牌不可成交。
- 涨停买入失败、跌停卖出失败。
- 买入整手和碎股卖出处理。
- 上市、退市、风险警示和证券状态变化。
- 分红送转、除权除息和复权处理。
- 佣金、最低佣金、印花税、过户费和其他费用参数。
- 固定滑点、比例滑点或成交量参与率模型。
- 订单相对市场成交量的容量限制。
- 部分成交和完全无法成交。

### 10.3 输出

回测至少输出：

- 净值、收益率、基准和超额收益。
- 回撤和恢复时间。
- 持仓与权重历史。
- 模拟交易、成交失败和未成交原因。
- 换手率、费用和滑点。
- 年度、月度和滚动绩效。
- 风险和归因明细。

## 11. Dashboard 需求

Dashboard 是本地研究运营台，不是策略代码编辑器。默认仅监听本机地址，不开放公网。

### 11.1 研究工作台

总览是只读的研究运营入口，先回答“当前是否可以开展可信研究”，再展示运行状态和
近期研究结果。数据更新、实验提交、任务重试等写操作仍由对应业务中心负责。

- 研究就绪状态必须包含研究门、阻断原因、最新交易日、验证时间和 Catalog 身份。
- 数据新鲜度、任务状态和实验状态使用全局聚合，不得用近期样本冒充全局分布。
- 活动任务只展示排队、运行和取消请求状态，并可深链接到运行详情。
- 待处理事项覆盖研究门阻断、质量阻断、数据缺失或滞后、失败任务和孤儿任务。
- ETF 轮动与股票多因子分别查询各自最近一次成功实验，不受最近实验列表窗口影响。
- 最近实验与基准结果必须链接到唯一实验；Notebook、数据中心和实验中心作为快捷入口。
- 每日行情、市场广度和估值等内容只在市场全景展示，不在总览重复计算。
- 市场全景核心指数固定为国证A指、上证50、沪深300、中证500和中证1000；BaoStock 可得的国证A指作为全市场基准优先展示。

Notebook 入口使用 Dashboard 内部 `/notebook` 路由，保留全局导航和页面标题，并在主内容区
内嵌独立运行于 `127.0.0.1:8009` 的 JupyterLab。Dashboard 通过只读
`/api/v1/notebook/status` 探测服务就绪状态，只有就绪后才挂载 iframe；未通过
`quant start` 启动 JupyterLab 时显示明确的本机启动提示。JupyterLab 继续作为独立进程
处理文件、内核、终端和 WebSocket，Dashboard 不代理或解释 Notebook 内容。

### 11.2 数据中心

- 数据资产列表直接展示 Canonical 数据集的开始日期、结束日期、记录数和最后更新时间。
- 质量运行详情按适用的“规则 × 数据集”展示 `PASS / FAIL / SKIPPED / UNKNOWN`、规则说明、通过条件和实际判断证据；历史运行缺少完整证据时不得以无问题推断通过。
- 失败规则关联缺失、重复、异常价格等具体问题及修复建议，规则说明采用运行时快照以保证历史解释稳定。
- BaoStock 下载、增量更新和接口错误状态。
- 创建更新任务时默认全选可执行数据集，并允许指定非空子集；预览自动增量或指定日期计划，并展开查看所选数据集的水位、重叠天数和确定执行窗口。
- 任务入库时固化已确认计划；预览后水位变化时拒绝旧计划并要求刷新。
- 部分更新仅抓取和发布所选 Canonical 数据集，随后仍执行全目录质量校验以维护研究门。
- 可在“创建更新任务”旁创建后台质量运行；默认执行全目录校验，也可选择单个数据集进行不影响研究门的诊断。
- 数据快照、来源和版本。
- 失败任务日志和安全重试入口。

### 11.3 实验中心

- 按策略、时间、标签和状态筛选实验。
- 查看参数、代码版本、数据版本和运行日志。
- 选择多个实验并排比较。
- 标记基线、候选或废弃。
- 添加研究结论和标签。
- 从已有实验复制配置并生成新实验 ID。
- 受审计地删除未活动实验；排队和运行中的实验必须先结束或取消。
- 删除实验会清理关联任务、产物和日志，但删除事件及历史审计继续保留。

### 11.4 回测分析

- 策略、基准和超额净值。
- 回撤曲线。
- 年度和月度收益。
- Sharpe、Sortino、Calmar、最大回撤和恢复时间。
- 持仓数量、换手、费用和滑点。
- 风格、个股和期间归因。
- 涨跌停、停牌和其他模拟成交失败统计。

### 11.5 因子分析

- RankIC 和滚动 RankIC。
- 因子分层收益。
- 因子覆盖率和缺失率。
- 因子间相关性。
- 因子方向、标准化和组合前后比较。
- 因子收益稳定性和年度表现。

### 11.6 运行中心

- 数据、因子、回测和报告任务列表。
- 排队、运行、成功、失败和取消状态。
- 运行时长和资源使用。
- 只读查看任务提交时的参数。
- 数据更新任务按业务语义展示更新模式、汇总范围和实际所选数据集的逐项执行窗口。
- 错误摘要与日志下钻。
- 因子分析任务可深链到其绑定的精确不可变运行，不得替换为所属研究的最新运行。
- 只对幂等任务提供重试。
- 数据更新重试复用原任务的固化计划；旧版未固化窗口的历史任务只能查看，不能重试。
- 只允许删除终态任务的运行记录与尝试索引；实验、产物、审计和日志文件继续保留。
- 长时间回测必须作为后台任务运行，关闭浏览器不影响任务。

### 11.7 Dashboard 禁止行为

- 直接修改 Raw 或 Curated 数据。
- 在页面中任意执行 Python 代码。
- 删除实验审计记录。
- 用新结果覆盖历史实验。
- 绕过实验登记直接发布正式报告。

## 12. 日常工作流

### 12.1 数据更新

```text
检查交易日
→ 增量下载 BaoStock 数据
→ 保存 Raw 数据
→ 标准化与复权
→ 更新证券状态和历史股票池
→ 执行数据质量检查
→ 生成数据快照
→ 更新可复用因子
→ 发布“可研究”状态
```

### 12.2 策略研究

```text
打开 Notebook
→ 选择数据快照
→ 编写或调用策略
→ 运行分析/回测
→ 登记实验
→ 查看报告
→ 在 Dashboard 比较
→ 记录研究结论
```

## 13. 错误处理与恢复

- 登录、下载、网络或限流失败采用有限次数退避重试；超过阈值后终止任务并记录错误。
- 关键字段缺失、交易日错误或全市场记录数异常时，禁止发布数据快照。
- 单只非关键证券异常可以隔离，但必须记录并在实验报告中披露。
- 回测失败保留最佳努力日志与已完成阶段，不登记为成功实验。
- 进程重启后识别未完成任务，避免重复写入。
- 所有任务使用唯一运行 ID 和检查点。
- 所有异常使用统一错误码、严重级别、上下文和建议处理方式。
- 重试不会覆盖原始输入、历史实验或已完成结果。

## 14. 非功能要求

### 14.1 性能

- 支持截至最新完整交易日向前滚动 20 年的沪深 A 股日频数据。
- 全市场股票多因子完整回测在验收机器上 60 分钟内完成。
- 单个 ETF 轮动完整回测目标在 5 分钟内完成。
- Dashboard 常规列表与指标查询目标在 3 秒内响应。
- 大型图表和归因查询目标在 10 秒内完成。
- 因子和中间结果支持缓存，参数变化不无条件重算全部原始数据。

性能验收必须记录 CPU、内存、磁盘类型、Python环境、数据区间、证券数量、因子数量和策略参数，保证结果可解释。

### 14.2 可复现性

- 相同代码、配置、数据快照和依赖环境得到相同结果。
- 每个实验绑定 Git 版本、环境版本和数据快照。
- 历史 Raw 数据和实验结果不可覆盖。
- Dashboard 指标可追溯至实验和输出文件。

### 14.3 可靠性

- 所有数据和研究任务必须幂等。
- 关键流程失败时不发布不完整数据或成功状态。
- 长任务支持状态查询、错误记录和安全重跑。
- SQLite 写操作采用事务，防止部分元数据落库。

### 14.4 安全与隐私

- Dashboard 默认仅在本机访问。
- BaoStock、TuShare 等凭据不写入代码、Notebook或Git。
- 凭据通过环境变量或本机安全配置加载。
- 日志不得输出完整令牌或密码。
- 一期不保存券商账户和真实交易凭据。

### 14.5 可维护性

- 核心模块提供类型提示和稳定公开接口。
- Notebook 只承担实验编排和解释性展示。
- 配置、交易规则和策略参数不散落在代码中。
- 数据源、策略、组合、回测、指标和展示保持单一职责。

## 15. 测试要求

### 15.1 单元测试

- 复权计算。
- 因子计算与处理。
- 交易费用。
- T+1 可卖约束。
- 涨跌停和停牌成交判断。
- 整手和资金取整。
- 组合约束。
- 绩效指标。

### 15.2 时点测试

- 公告前财务数据不可见。
- 历史股票池不使用未来风险、退市或成分状态。
- 信号日和最早成交日严格分离。
- 数据修订不悄然改变旧实验绑定的快照。

### 15.3 集成测试

- BaoStock 适配器到 Raw 层。
- Raw 到 Curated 和 Feature 层。
- Notebook 调用正式回测 API。
- 实验登记到 Dashboard 查询。
- 后台长任务状态更新与失败恢复。

### 15.4 回归测试

使用固定的小型数据集保存黄金结果，至少覆盖：

- 股票池。
- 因子值和排名。
- 目标权重。
- 模拟成交。
- 净值和关键绩效指标。

代码变更引起黄金结果变化时，必须明确审阅和更新原因。

### 15.5 性能测试

- 使用截至验收日最新完整交易日向前滚动 20 年的全沪深 A 股日频数据执行股票多因子完整回测。
- 记录阶段耗时、峰值内存、缓存命中和输出规模。
- 总时间不得超过 60 分钟。

## 16. 一期验收标准

一期同时满足以下条件方可验收：

1. BaoStock 数据可以完成初次全量导入和后续增量更新。
2. 数据形成版本化 Raw、Curated、Feature 层及可研究快照。
3. 关键数据质量失败会阻止快照发布。
4. ETF 轮动示例可从 Notebook 完整运行、登记并在 Dashboard 展示。
5. 股票多因子示例可从 Notebook 完整运行、登记并在 Dashboard 展示。
6. 回测正确处理已确认的 A 股核心交易约束。
7. 实验可以登记、复现、比较、标记和导出报告。
8. Dashboard 六个页面可用。
9. 后台回测不依赖浏览器持续打开。
10. 模拟 TuShare 适配器测试证明策略、回测和 Dashboard 不依赖 BaoStock 专有模型。
11. 单元、时点、集成和回归测试通过。
12. 不存在未解释的严重或致命数据质量问题。
13. 在记录配置的验收机器上，20 年全市场股票多因子完整回测不超过 60 分钟。

## 17. 长期阶段规划

### 阶段一：研究与回测

即本文 MVP：数据、实验室、两类策略、可信回测、实验登记和 Dashboard。

### 阶段二：组合与模拟运营

- 多策略资金分配。
- 目标组合管理。
- 模拟账户和模拟成交。
- 每日组合监控。
- 研究结果到候选生产策略的审批流程。

### 阶段三：半自动实盘

- 券商适配器。
- 程序化交易报备前置检查。
- 订单草案、事前风控和人工审批。
- 成交回报、内部账本和每日对账。
- Kill Switch 和异常恢复。

### 阶段四：稳定运营

- 多策略风险预算。
- 备用数据源和跨源质量监控。
- 灾难恢复和备份演练。
- 在合规、风控和稳定性满足要求后评估自动化程度。

后续阶段必须分别形成新的需求规格和实施计划，不自动纳入一期范围。

## 18. 主要风险与控制

| 风险 | 控制要求 |
|---|---|
| 未来函数 | 时点数据接口、公告时间校验、专门时点测试 |
| 幸存者偏差 | 历史证券主数据、退市与风险状态保留 |
| 数据源绑定 | SourceClient 与 CanonicalMapper 分离，统一 Curated 领域模型 |
| 历史数据被修订 | Raw 不可变、快照版本绑定实验 |
| Notebook 逻辑失控 | 核心逻辑提升至正式包并测试 |
| 回测过度乐观 | T+1、涨跌停、停牌、费用、滑点和容量约束 |
| 参数过拟合 | 实验登记、样本外验证、参数稳定性分析 |
| 全市场性能不足 | Parquet 分区、DuckDB/Polars、分批计算、阶段性能分析 |
| Dashboard 阻塞任务 | 长任务后台运行，前端只查询状态 |
| 结果不可解释 | 保存代码、配置、数据、环境、日志和归因 |

## 19. 完成定义

一期系统的完成定义不是获得某个收益率，而是达到以下工程结果：

> 任意已登记实验都能追溯到代码、配置和数据快照；同一实验可复现；回测不使用未来信息并模拟关键 A 股约束；20 年全市场多因子研究在 60 分钟内完成；研究结果能够在本地 Dashboard 中稳定比较和解释。
